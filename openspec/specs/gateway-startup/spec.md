# gateway-startup

Запуск шлюза Hermes (`hermes gateway run` и его старт через `hermes gateway ensure` из Desktop):
восстановление сессий прошлого владельца и переход в состояние `ready`. Desktop ждёт готовности
шлюза 60 с; шлюз, чей цикл событий не отвечает, сторож `shutdown_watchdog` завершает кодом 75.

## Requirements

### Requirement: Старт шлюза без WAL не блокирует цикл событий

Восстановление сессий при старте шлюза (в том числе `arm_startup_orphan_closes`) ДОЛЖНО завершаться,
когда база состояний работает без WAL (`journal_mode=DELETE`, например при SQLite, уязвимой к
WAL-reset). Код шлюза НЕ ДОЛЖЕН открывать read-контекст `SessionDB` внутри другого, ещё открытого
read-контекста той же базы в том же потоке: без WAL оба держат одну нереентерабельную блокировку.

#### Scenario: Сессии-сироты после аварийного выхода, SQLite без WAL

- **Given** прошлый шлюз завершился аварийно и оставил локальные сессии без зрителей
- **And** база состояний открыта без WAL
- **When** новый шлюз при старте вооружает закрытие сирот и считает их простой (`_idle_s`)
- **Then** вычисление простоя завершается без ожидания блокировки, которую держит тот же поток
- **And** шлюз становится готовым, `hermes gateway ensure` отвечает `ready`

#### Scenario: Регрессионный тест ловит вложенный read-контекст

- **Given** `SessionDB` с `_wal_active = False` и блокировкой, которая при повторном захвате
  падает через 5 с
- **When** тест вызывает `_idle_s` для существующей сессии
- **Then** тест проходит на исправленном коде
- **And** на коде с вложенным `_read_ctx` тест падает с `AssertionError`, а не зависает
